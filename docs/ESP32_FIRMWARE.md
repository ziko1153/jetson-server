# ESP32 firmware

The firmware is a PlatformIO project at `firmware/esp32`. It is the water-mount controller: three STEP/DIR drivers for pan, tilt 1, and tilt 2. It speaks `docs/RCWM_SERIAL_PROTOCOL.md` at 115200 baud by default. Step pulses are generated by FastAccelStepper on the RMT peripheral; the ramp itself is owned by the motion planner, which follows the per-axis limits sent from the ground station.

## Confirmed pin map (ESP32 DevKit V1)

`firmware/esp32/include/board.hpp` carries the confirmed wiring:

| Axis | STEP (PUL+) | DIR (DIR+) | ENABLE (ENA+, optional) |
| --- | --- | --- | --- |
| pan | GPIO 18 | GPIO 19 | GPIO 25 |
| tilt 1 | GPIO 22 | GPIO 23 | GPIO 32 |
| tilt 2 | GPIO 26 | GPIO 27 | GPIO 33 |

PUL-/DIR-/ENA- all tie to ESP32 GND. The STEP/DIR pairs are required per axis. ENABLE is optional per axis: leave it at `-1` while the driver ENA input is unwired and set `kEnablePolarity` (0 active low, 1 active high) only when at least one enable pin is wired. With a pin set, the firmware auto-enables on motion and releases the driver shortly after a stop. None of these GPIOs are input-only, flash, or strapping pins.

## Commissioning gates

Before commanding real motors, an operator has to:

1. Confirm a physical emergency stop removes motor power without help from the ESP32 or the Jetson.
2. Set `rcwm.serial_port` to the port the operating system assigned, and keep `rcwm.allow_hardware_motion` false until step 1 is done. The Jetson then still forwards everything except MOTION frames over the serial link; STOP is always sent.
3. Set speed, acceleration, deceleration, and travel limits from the ground station. The firmware does not choose them from the motor size and persists them in NVS on the ESP32.

Software stop and the link timeout release the software enable output. They are not the emergency stop. Position values are step counts, not encoder readings. The controller persists the last halted position, so a reboot keeps the angle and the reference; if the mount is moved by hand while powered off, the stored angle is wrong until Set home is pressed again.

## Host test

The motion math and the frame codec build without an ESP32 or PlatformIO:

```bash
bash scripts/test-firmware-host.sh
```

That compile does not flash a board and does not move a motor.

## Build and flash

Install PlatformIO on the machine that has the USB cable. This repository's setup scripts do not install it and do not upload firmware.

```bash
cd firmware/esp32
pio run -e esp32dev
pio run -e esp32dev -t upload --upload-port /dev/cu.usbserial-XXXX
pio device monitor -b 115200
```

Use the port the operating system actually assigns. On macOS that is usually `/dev/cu.usbserial-*` or `/dev/cu.usbmodem*`. On the Jetson it is often `/dev/ttyACM0` or `/dev/ttyUSB0`, but only after the device enumerates. Put that path in `rcwm.serial_port`. Do not leave a guessed path in `board.hpp` or in the default config.

The Jetson user must be able to open the port, for example as a member of `dialout`. `scripts/setup-jetson.sh` prints that hint and does not change group membership itself.

Upload is a manual step. Nothing in `scripts/start.sh` flashes the ESP32 or enables the drivers.
